> 背景脱敏：一个 Go 微服务架构的游戏后端，用 kube-prometheus-stack 做中央监控栈，正式服指标经 remote_write 汇入。两个月里陆续实锤了几批「加载成功但从未工作过」的告警配置：21 条因 Helm 占位符没渲染、11 条业务告警从未 apply、59 条选择器匹配不到任何序列。本文记录这些失效模式，以及最后为什么把验证交给了机器。

## 现象：告警存在、语法正确、Prometheus 也加载了

一次正式服压测，3200 人档成功率跌到 21.3%，全程零告警。一台宿主内存 97% 打爆、监控栈全盲，也是零告警。事后查，规则都在，`/api/v1/rules` 里能看到，health 全是 ok。

它们只是从来没有匹配到过任何序列。

## 五种失效方式

### 1. Helm 占位符以字面量进了线上正则

规则写在 kube-prometheus-stack 的 `additionalPrometheusRulesMap` 里，为了复用命名空间清单，表达式用了 `{{ .Values.businessNamespaces }}`。chart 不渲染这一段里的 `.Values` 占位符，占位符原样进入线上正则，永不匹配，health 恒 ok。从 6 月 8 日到 8 月 17 日，21 条告警从未触发。

修法只能是写字面量，两处同步改。配套加了门禁，拦 `.Values/.Release/.Chart/.Capabilities`，不拦 `{{ $labels.* }}` 这种告警渲染期的合法模板：

```bash
grep -nE '\{\{[^}]*\.(Values|Release|Chart|Capabilities)[^}]*\}\}' "${VALUES}" \
  | grep -vE '^[0-9]+:[[:space:]]*#'
```

这条门禁必须放在 promtool 守卫之前：CI 镜像里没有 promtool，放后面等于从未运行。

### 2. 规则合入了主干，从未 apply

业务告警文件里 11 条规则（登录封禁失效、道具流水丢失、支付订单卡单等）在 8 月 13 日之前从未被 apply 过：中央栈 221 条告警里一条都不在。另一组 8 条节点 CPU 告警合入主干后也从未上线，线上 CR 的 `creationTimestamp` 停在合入前一天。

放大器是部署脚本只 apply exporter 与 webhook，从不 apply 任何 PrometheusRule，规则全靠人工敲 kubectl，漏一次即静默失效且零反馈。判据一句话：

```bash
kubectl get prometheusrule <名> -o jsonpath='{.spec.groups[*].name}'
```

与仓库文件里的组名比对。

### 3. 选择器引用了运行时不存在的东西

同一天实锤三处，是同一类病的三种形态：

| 配置 | 失效方式 |
|---|---|
| 节点内存告警 | expr 过滤 `job="node-exporter"`，本栈 job 实为 `k3s-node-exporter`/`prod-node-exporter`，两条告警自上线起匹配不到任何序列。这条本身就是前一天宿主 OOM 复盘的预防措施，**复盘产出的预防措施自己就是空转的** |
| alertmanager inhibit | 告警名 `NodeDown` 不存在（真实为 `KubeNodeNotReady`），且 `equal:[instance]` 两侧格式不同永不相等。节点失联时被数十条 Pod 级告警轰炸 |
| 退役服务的死面板 | 大厅单体退役后 8 个面板 + 1 条告警引用零上报方指标，恒 No data |

三者的加载器（prometheus-operator / alertmanager / grafana sidecar）都只校验语法，不校验引用目标存在。

### 4. 埋点喂不进

「对局开始速率」「匹配耗时 P99」面板长期空，一度被判为环境空载。实测窗口内在线 3000、活跃桌 800，指标仍贴 0。两条根因：一条埋点挂在 `SetState(StateRoundStart)` 上，而主力玩法走自己的状态机从不切这个状态；另一条在一次大重构迁移时 `- metrics.ObserveMatchDurationSeconds(...)` 被删了没重接，全仓只剩单测在调。正式服那 3 次观测是预注册的 `Observe(0)`。

预注册的 0 值会冒充「已接入」。验证只能是在有流量的环境查 `increase(<指标>[2h]) > 0`。

### 5. kubectl apply 生效了又被 selfHeal 抹掉

后来规则改由 GitOps 管：ArgoCD 从独立的 infra 仓同步全部 PrometheusRule 到中央栈，`syncPolicy = automated + selfHeal + prune`。此后任何 `kubectl apply` 直接写集群的规则改动会在几分钟内被 selfHeal 静默回退，症状是「生效了又消失」。

而源码仓里那份 `deploy/monitoring/*.yaml` 只是草稿。一条新告警合入源码仓后，中央栈 318 条规则里没有它，正因为只改了源码仓没动 infra 仓。文件头注释还写着旧的 `make monitoring-deploy` 口径，被自己仓库的过时注释误导，给用户开出了错误待办。**判断部署真源先查集群里的 ArgoCD Application，不信注释。**

## 双栈各存一份

还有一层结构性的：正式服是裸 Prometheus 不吃 CRD，规则只能落在中央栈；中央栈同时汇聚正式服、测试集群、独立 K3s 三套环境的指标。每条 expr 都必须带 `cluster="prod"`，实测同一指标的 cluster 取值分布是 测试集群:37 / 正式服:7 / 独立集群:6，不加选择器的后果是测试环境的抖动冒充正式服告警把人叫起来，而正式服自己的信号被其它环境稀释后报不出来。

## 根治：真源 + 每日巡检 + 漂移门禁

人的检查靠不住，三处空转的作者（含 AI 会话）都止步于「apply 成功 + 页面上能看到」，没有一个当场跑一句 `count(<选择器>)`。所以交给机器。

**真源**：规则的唯一生效路径是 GitOps。源码仓合入主干后由 CI 单向投影到 infra 仓，两仓文件逐字一致（diff 为空才算对齐），手工提交 infra 仓既是 no-op 也违背单向纪律。

**活性体检脚本**：对运行中的 Prometheus / AlertManager 验证三件事：

- 检查 A：每条 alerting rule 的选择器能否匹配到真实序列
- 检查 B：inhibit 的 alertname matcher 是否指向真实存在的规则名
- 检查 C：仓库告警名 ⊆ 线上已加载告警名（A/B 只体检「已加载的」，天生查不出「压根没上线」）

判据设计是脚本能用的关键，要对稀疏事件型指标免疫：指标近 7 天零序列，疑似退役；label 匹配值不在该指标实际取值域（`count by (label)`），写错；组合为空但各 label 都在取值域，是 `result="failed"` 这类事件型计数器，不报。取值域比对必须用 `count_over_time[7d]` 窗口，瞬时取值域会误报。

首跑抓出存量 59 条。逐条定性后全部清零：27 条是 helm 默认规则过滤 `job="node-exporter"` 的同一病根，关默认组、按真实 job 重建；一条已退役 110 天的数据库监控链路整体删除；chart 模板里 2 条恒空告警删除；4 条 kube-state-metrics 告警靠开 selfMonitor 修好。线上实测 PASS 244 条 0 FAIL 后转严格模式。

**反向验证是关键**：一条新告警未 apply 时先跑一次，检查 C 精确报出该条且 250 多条零误报；apply 后复跑 `PASS: 253 条`。只看一次绿等于没验。

## 告警常亮等于没有告警

治理过程里最值钱的发现不是空转，是反面：一台节点从 08:36 报到 11:16 崩掉，2 小时 40 分钟无人反应。查因是另一台节点过去 7 天 100% 的时间都在报同一条内存告警。新告警阈值一律按实测基线留 13~25 倍余量。

变体是噪音淹没信号：磁盘告警只排除了 `fstype!~"tmpfs|overlay"`，没排 mountpoint，`/var/lib/kubelet/pods/*/volume-subpath` 这些与根分区是同一块盘，一块盘满按挂载点数量重复告警，实测一次故障刷 88 条。查告警有效性不能只看「有没有规则、规则有没有 apply」，还要看**一次故障产生几条**。

## 教训

- **配置加载成功 ≠ 配置在工作**。规则出现在 `/api/v1/rules`、inhibit 出现在 config、面板正常渲染，都不证明它们匹配得到东西。判「生效」只能靠观察它真的动过一次。
- **新监控资产的完成判据 = 当场对运行时验证匹配**：规则跑 `count(<选择器>) > 0`，inhibit 验 alertname 存在，面板保存后非 No data。「apply 成功」三个字不构成验证。
- **复盘产出的预防措施也要过同一道验证**。若预防措施是监控配置，交付清单里必须附一条实测匹配的证据。
- **服务退役的收口清单必须包含监控资产**：面板、告警、指标常量与上报函数，按「调用方计数归零」逐条清点。判死指标要 grep 该指标全部写入函数，按 `Set` 前缀漏了 `Inc/Dec`，误删了一个活面板。
- **同一面板反复修 ≥3 次，停手查架构**。看板空白被连贴 6 个 PromQL 补丁，实际是抓取端口配错，业务指标整体缺失。
